# 孙熙桐的博客

个人博客，独立于现有个人工作台。前台使用 Astro、TypeScript 生成静态页面；写作后台使用 React、Tiptap；阿里云 Supabase 提供数据库、管理员登录、图片存储和留言接口。博客名称、署名和个人介绍可在后台调整，源码中的初始名称仍为「Sun XT 的博客」。

目前网站已部署到 GitHub Pages，仍标记为「开发预览」。文章和个人资料通过构建部署更新；留言直接读取数据库，不等待文章部署。AI 摘要保留了实现，但尚未接通并启用。

## 写作、摘要与图片

1. 在后台「文章」点击「写一篇文章」，填写标题、正文和分类。分类按「日常记录、研究札记、视频文案」排列，新文章默认「日常记录」。
2. 点击「保存草稿」保存到云端。当前没有定时自动保存；「预览文章」展示当前编辑内容，不等于已经保存或发布。
3. 点击「发布文章」。程序会先保存当前草稿，再提交整站发布快照；等待发布状态变为「已上线」后查看公开页面。修改已上线文章后，也需要重新发布。

- 编辑器支持标题、粗体、斜体、列表、引用、HTTPS／邮箱链接、图片和代码块。公开文章提供目录、代码高亮及较新／较早文章导航。
- 摘要可以手写。保存时若摘要为空，会提取正文纯文本的前 120 个字符；这不是 AI 总结。已经保存的摘要不会随正文自动更新，需要手动修改，或清空后再次保存。
- 正文和封面上传支持 JPG、PNG、WebP、GIF，单张不超过 5 MB。通过后台上传的草稿图片位于私有桶，管理员通过临时签名链接预览；签名链接有效期为一小时，不应分享。
- 发布时会把正文和封面中的私有上传图片复制到公开桶，并把公开地址写入发布快照。自行填写的外部图片地址需要使用 HTTPS，其可见性由图片来源决定。
- 文章地址只接受小写英文、数字和短横线，最长 100 个字符；已发布文章的地址在编辑界面中锁定。
- 「撤回」保留后台草稿；「移除」将草稿标记为已删除，后台没有自助恢复入口。两者都要等新部署完成后才从公开页面移除。

文章分类筛选位于「文章」列表上方，可与标题、摘要和正文的关键词搜索组合使用。搜索在浏览器中匹配已部署的公开文章，不搜索草稿；分类会保存在网址中，关键词不会。原分类页跳转到文章列表的对应筛选结果。文章和作品均不使用标签。

## 发布过程与状态提醒

后台提交 → Supabase 生成发布快照并排队 → GitHub Actions 领取快照 → 测试、类型检查和构建 → 部署 GitHub Pages → 回写上线状态。

- 后台文章状态和发布记录每 5 秒检查一次。「请求已提交」「等待发布」只表示入队，不代表已经上线；有未发布修改、部署失败和状态无法确认时会分别提示。
- 「发布记录」显示最近 15 条记录，并自动列出相对上一条保留的提交版本改了什么：文章新增、正文／排版、摘要、分类、封面、精选状态及从公开版本移除，个人资料字段的前后值，以及作品的新增、修改、移除和顺序变化。内容相同时明确显示「没有内容变化」，首个保留版本或不完整历史不会编造修改原因。这里比较的是提交版本，不能据此认定内容已经上线，也无法仅凭历史快照区分撤回与删除；网站代码改动仍查看 GitHub 提交记录。
- 文章状态位于「发布文章」按钮下。「发布资料」及「重新发布当前内容」按钮下也会显示本页提交的进度。
- 保存、发布、撤回、移除和重试等操作会在右下角提醒。普通成功提醒约 8 秒后消失；等待、部署中和失败提醒保留到关闭或后续状态更新。状态变化提醒只追踪本页提交的请求，刷新页面后仍可查看文章状态与发布记录。
- GitHub 定时任务计划每 2 小时检查队列，时间为北京时间 00:02、02:02、04:02……22:02；实际执行可能延迟，不保证两小时内上线。后台在等待满 2 小时后显示「等待时间较长」。也可从后台的「查看部署／手动启动」打开工作流，选择 `Run workflow`；不填写版本编号时会优先领取最新待发布快照，没有待发布内容则重建当前在线版本。
- 定时检查处理文章发布、重新发布、撤回、移除，以及已提交发布的个人资料和作品。不发布仅保存的草稿；留言不等待此任务，源码推送到 `main` 仍直接触发部署。
- 队列优先部署最新快照，较早的待发布请求可能显示为「历史版本」或「已被新版本替代」。构建或部署失败时，上次在线页面保留；重试会创建新的发布请求。
- 每次请求生成的是整站快照，包含准备发布的文章集合和当时已保存的站点资料。因此发布文章、撤回、移除或重试时，也可能带上已经保存、尚未单独发布的资料；未点击发布的文章草稿不会因此进入快照。
- 若 GitHub Pages 已部署成功，但状态回写失败，页面可能已更新而后台仍未确认。应先核对 GitHub Actions 的实际部署结果，再处理状态同步。

当前云端发布接口只把快照放入队列，不主动请求 GitHub 启动工作流。GitHub 构建只读取用于公开发布的快照，状态回写使用服务端回调密钥。

### GitHub 提交与博客发布的区别

[`deploy.yml`](.github/workflows/deploy.yml) 有三种触发方式：`main` 分支收到推送、定时检查、手动运行。代码推送会用当前在线快照重建网站，不直接领取待发布文章；定时任务在没有待发布快照时跳过构建。

工作流没有自动合并外部 PR 的步骤，也没有 PR 提交触发器。谁能向仓库或 `main` 写入，取决于 GitHub 账号、协作者、应用／令牌授权及分支规则；公开可见不授予写入权限，测试通过也不代表经过人工审核。具体协作者和审核规则以 GitHub 仓库设置为准。

源码推送所用的 Git 授权，与本地首次设置页保存的发布令牌是两套配置。

## 留言

- 访客无需注册，可在文章下方和独立留言板提交纯文本留言，提交后公开。昵称可选，留空显示「访客」；昵称最多 30 字，留言最多 1,000 字。
- 提交者成功提交后立即看到留言；其他已打开的页面每 10 秒从数据库刷新一次。这里使用定时读取，没有使用 Supabase Realtime 推送，也不需要重建网站。
- 后台「留言管理」显示最近 100 条未移除留言，每 10 秒刷新。移除后数据库不再向访客返回该条内容；其他已打开页面在下次成功刷新时更新。
- 留言经 `blog-message` 接口校验隐藏字段、长度及文章状态，再由数据库原子限流。同一浏览器访客标识在一分钟窗口内最多提交 3 次；不是按 IP 或真实身份限流，清除或更换浏览器标识可以绕过，当前未接额外人机验证。

## 本地开发与检查

使用 Node.js 24，在仓库目录执行：

```sh
npm ci
npm run dev
```

默认开发地址为 `http://127.0.0.1:4321/personal-blog/`。开发页面使用本地已有的 `src/data/snapshot.json`；没有该文件时显示源码默认内容。运行构建会从云端读取当前在线公开快照并更新该文件，因此构建需要网络和可用的 Supabase 服务。

| 命令 | 用途 |
| --- | --- |
| `npm test` | 验证内容处理、搜索、发布队列与状态、提醒、GitHub 初始化及摘要逻辑等；不等同于完整云端验收 |
| `npm run check` | Astro／TypeScript 检查 |
| `npm run build` | 读取公开快照并生成 `dist/`；读取失败则停止构建 |

GitHub Actions 使用 `npm ci`，随后运行测试、类型检查和构建。可用环境变量 `ASTRO_TELEMETRY_DISABLED=1` 关闭 Astro 使用统计。

本地维护脚本依赖已配置的阿里云 Supabase MCP：从本机 Codex 配置读取连接凭据，并使用本地已缓存的 MCP 组件连接项目 `spb-9wis0ky4nvb4lvh5`、地域 `cn-hangzhou`。脚本为此次连接启用所需写入，不修改全局连接设置。

| 命令 | 本机地址与作用 |
| --- | --- |

| `npm run setup:summary` | `http://127.0.0.1:4392/`，保存百炼配置，默认不启用 AI 摘要 |

配置页只监听 `127.0.0.1`，必须在相应程序运行期间从这台电脑访问，不会部署到 GitHub Pages。完成后可关闭页面，并在启动程序的终端按 Ctrl+C 停止服务。

### 数据库与后台接口

[`supabase/migrations/`](supabase/migrations/) 按编号保存数据库更新。`node scripts/migrate.mjs` 只备份现有工作台数据和权限并执行 `001_blog.sql`，不会自动执行 `002`～`008`，不能把它当成完整升级命令。

- `002`、`003`：工作台管理员权限和匿名访问收紧；历史入口为 `scripts/secure-workbench.mjs` 的 `stage`／`protect`。该脚本包含初始化时的记录数断言，重新使用前需核对现有数据和登录页面。
- `004`：公开发布队列及部署状态处理；`005`、`006`：文章发布状态与草稿来源版本；`007`：摘要调用限流。
- `008`：迁移并限制为三个文章分类，公开快照不再输出文章或作品标签；历史标签列和历史快照保留兼容，分类更新不改正文、文章地址和版本时间。

新环境需核对并按顺序应用所需更新；现有环境应先确认已应用的版本和备份，不重复初始化。工作台权限收紧需在管理员登录和工作台登录页面验证完成后执行。

后台接口源码位于 [`supabase/functions/`](supabase/functions/)，与 GitHub Pages 分开部署。维护接口时先打包，再部署：

```sh
node scripts/build-functions.mjs
node scripts/deploy-functions.mjs
```

第二条命令默认部署 `blog-message`、`blog-publish`、`blog-release-status`、`blog-summary` 四个接口，也可传入其中一个名称，只部署该接口。普通源码推送只构建和部署网站，不会自动更新数据库或后台接口。维护命令使用云端管理权限，只在可信本机运行。

### AI 摘要的当前状态

百炼云端连接此前验证超时，尚未启用；目前使用手写摘要或正文截取。未为此新增付费公网出口，也未启用本地代理方案。

仓库保留了配置页、`blog-summary` 接口及候选摘要界面，供将来接通服务端网络后继续完成。保存 API Key 本身不会调用模型或启用功能；只有后台「验证并启用」调用成功后才能生成。启用后仅管理员可调用，每分钟最多 3 次，标题和正文会发送给百炼，按服务商用量计费；候选结果需点击「采用摘要」，再保存或发布。

## 数据权限与备份

- 管理员需通过邮箱密码登录，并且用户 ID 位于 `blog_admins`；普通登录账号不会自动获得管理权限。权限由数据库 RLS 和后台接口检查执行。
- 前端包含 Supabase 地址和公开访问密钥。服务端高权限密钥、GitHub 发布令牌、回调密钥及百炼 API Key 不应提交到仓库或发送到聊天中；发布配置表不对访客及普通登录会话开放。
- 访客可读取用于公开发布的快照和允许显示的留言，不能直接写入留言表、读取草稿或工作台私人数据、修改文章及站点设置。点击发布后，生成的快照和复制出的图片按公开内容处理，上线仍需等待部署。
- `.private/` 存放本机备份、初始化结果、接口打包文件和检查截图，被 Git 忽略；这不等于加密或异地备份，需自行妥善保管。`src/data/snapshot.json`、`.env`、依赖及构建目录也被忽略。
- 博客表使用 `blog_` 前缀。工作台仍在原有数据表中，维护和权限迁移不得删除或覆盖原有记录。

## 开发预览限制

- 所有页面目前设置 `noindex,nofollow`；站点地图和 RSS 尚未实现。正式运营前需确定生产服务并调整收录配置。
- 现有阿里云项目按开发预览方案使用，当前方案没有为博客另购云资源或域名。
- GitHub 定时任务可能延迟或被暂停。长时间等待时先检查 [Actions 发布页](https://github.com/Sun-XT9527/personal-blog/actions/workflows/deploy.yml)，按需启用工作流并手动运行。
- 已生成的文章在撤回或移除后，需要等待新部署才从站点消失。浏览器缓存、已下载内容和公开图片链接不会随文章撤回自动清除。
