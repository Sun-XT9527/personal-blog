# Sun XT 的博客

独立于个人工作台的开发预览博客：Astro 静态文章、React 写作后台、Tiptap 可视化编辑器，以及阿里云 Supabase 数据、登录、图片和即时留言。

## 日常使用

- 首页：`https://sun-xt9527.github.io/personal-blog/`
- 后台：在博客页脚点击「管理后台」，或访问 `https://sun-xt9527.github.io/personal-blog/write/`，使用首次设置时的邮箱和密码登录。原 `/admin/` 地址继续可用。
- 写作：新建文章 → 保存草稿 → 私人预览 → 发布。发布记录变为「已上线」后，公开页面更新。
- 编辑页和文章列表会直接显示每篇文章的发布状态，每五秒检查一次。只有实际在线版本更新后才显示「已上线」；排队、部署中、失败及后续未发布修改会分别提示。排队超过五分钟时提供延迟提示和手动部署入口。
- 发布状态位于编辑侧栏的「发布文章」按钮下方。
- 摘要支持手写和百炼 AI 候选摘要。只有在模型连接验证成功后才启用 AI；生成结果需点击「采用摘要」，之后仍要保存或发布。模型调用仅管理员可用，每分钟最多三次，标题与正文会发送给百炼，密钥仅由服务端持有。
- 发布任务由 GitHub 每五分钟检查一次，排队和部署可能需要更长时间。在「发布记录」点击「查看部署／手动启动」，可以从 GitHub 的 Run workflow 立即领取待发布任务，无需填写版本编号。
- 个人介绍和作品：在「个人与站点」保存资料，再点击「发布资料」。
- 「关于」页正文对应「个人与站点 → 关于我」；页面姓名和 GitHub 链接对应「署名」和「GitHub 链接」。B站、抖音和小红书链接在「我的其他主页」修改，留空隐藏。页首介绍短句、侧栏短句和「为什么写这个博客」属于固定文案。
- 文章分类依次为「日常记录、研究札记、视频文案」，新文章默认「日常记录」。项目、工具放在「个人与站点 → 作品展示」，发布后显示于「作品」页。文章和作品均不使用标签。
- 分类筛选合并在「文章」页顶部，可与全文搜索组合；筛选后的地址可分享，刷新和浏览器返回保留分类。原分类地址跳转到文章页的对应筛选结果。
- 留言：文章下方和留言板即时公开，后台可移除。最多 1,000 字，同一浏览器访客每分钟最多 3 次；该基础拦截无法防止访客清除浏览器标识绕过限制。

## 本地开发

需要 Node.js 24。执行 `npm ci`，然后 `npm run dev`。默认地址为 `http://127.0.0.1:4321/personal-blog/`。

`npm test` 验证内容安全、目录和代码高亮；`npm run check` 检查类型；`npm run build` 读取公开快照并生成静态页面。

可以将 `ASTRO_TELEMETRY_DISABLED=1` 配置为本地环境变量，关闭 Astro 使用统计。

## 首次配置

在已连接阿里云 MCP 的 Windows 电脑上执行 `npm run setup`，访问程序打印的本机设置地址。管理员密码由你自己填写，不进入聊天或源码。

GitHub 使用仅针对 `Sun-XT9527/personal-blog` 的细粒度发布令牌。首次自动配置需要 Actions、Contents、Pages、Secrets 的读写权限。设置页面将回调密钥加密保存到 GitHub Actions，将发布令牌保存到 Supabase 仅服务端可访问的 `blog_runtime_config`。后续可将发布令牌缩减为仅 Actions 读写权限。

阿里云连接保持当前项目 ID，初始化脚本在任务专用连接中启用方案所需写入，不修改全局连接设置。

数据库初始化：`node scripts/migrate.mjs`。边缘函数：先执行 `node scripts/build-functions.mjs`，成功后执行 `node scripts/deploy-functions.mjs`。这些命令需要管理员云凭据，仅在可信本机执行。

栏目调整使用 `008_blog_categories_without_tags.sql`：迁移分类并限制为三个栏目，公开快照不再包含文章和作品标签；历史快照和数据库标签列保留兼容。迁移不更新正文、文章地址或版本时间，执行前应备份分类字段；本次备份及正文校验值位于被 Git 忽略的 `.private/`。

现有项目出公网受限。后台通过阿里云提供的 `SUPABASE_LOCAL_URL` 访问本地网关；发布快照入队，由 GitHub 主动读取公开版本并部署。新增数据库迁移 `004_publication_queue.sql` 提供公开队列编号，构建不需要高权限数据库密钥。

百炼摘要配置：在可信电脑运行 `npm run setup:summary`，由管理员本人在打印的本机页面填写 API Key、模型和官方接口地址。密钥保存到私有服务端配置并默认禁用；在写作后台点击「重新检查连接」，再通过「验证并启用」完成一次模型调用后启用。验证会消耗少量模型用量。当前 Supabase 至百炼的外网请求实测超时，须先确定并接通服务端网络；未接通时不能宣称 AI 摘要可用，也不会回退成前端携带密钥的调用。

## 权限与备份

- 公开代码中只有公开访问密钥，高权限密钥不进入源码、文件或日志。
- 草稿、管理员列表、站点待发布资料和发布配置禁止访客读取。草稿图片存于私有桶；发布时复制为公开图片。
- 公开页面只从不可变的发布快照构建。直接写入留言表被禁止，留言必须经过服务端接口和数据库原子限流。
- `.private/` 保存本地备份和初始化结果，被 Git 忽略。请保留并自行备份该目录。
- 工作台权限切换必须在管理员创建及登录验证完成后执行；原有数据不得删除或覆盖。

## 开发预览限制

当前阿里云免费项目仅用于开发测试。此博客设置 `noindex,nofollow`，正式上线应先确定生产服务，再开启收录、站点地图和 RSS。GitHub Pages 上已生成的文章在撤回或删除后，需要等待新部署完成才从站点移除；浏览器缓存和已分享的内容无法自动撤销。

GitHub 定时任务可能延迟；公共仓库长期无活动时，GitHub 会在 60 天后停用定时任务。遇到发布长期等待，请在 Actions 页面启用工作流并手动运行一次。预览阶段未新增公网 IP 或 NAT 网关等付费资源。

发布版本失败时保留上次在线页面，可以从后台重试。若页面部署成功但状态同步失败，应核对 GitHub Actions 后重新同步状态，避免误认为文章未上线。
